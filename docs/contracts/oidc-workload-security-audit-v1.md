# OIDC workload security audit v1

Additive TASK 003 contract for the [new Python boundary](python-oidc-workload-v1.md). Existing [Security Audit v1](security-audit-v1.md) events, actors, metadata, databases and producers remain unchanged. This extension uses its own explicitly configured SQLite file and schema version 1; no historical migration is edited and no new audit service is created.

Every enabled-boundary request records one `workload_authentication` event before returning an allowed projection or a normal denial. Fixed action `authenticate_workload`, source `ai-service`, route `/iam-lab/v1/workload-context`, contract `oidc-workload-security-audit-v1`. Fields are UUIDv4 event/correlation ids, UTC timestamp, outcome, bounded reason, actor type, optional internal principal/organization and registered provider id. No arbitrary metadata, issuer, subject, client-supplied identity, permission list, token/hash, cookie, header, request payload, key/JWKS or clinical data is stored.

Allowed rows use `workload` and the trusted internal principal/organization. Denials use `anonymous` and null identity/organization: no partially verified principal is attributed. Provider id is included only from validated local configuration. Reasons distinguish missing/ambiguous/malformed credentials, untrusted issuer, audience/purpose/signature/time/key verification failures, unknown binding, disabled principal/binding, organization/policy denial, incomplete/disabled configuration and provider/key availability.

The append API validates a closed reason vocabulary and field combinations before one parameterized `BEGIN IMMEDIATE` insert/commit. A boundary-owned writer lock serializes initialization/appends within the process, including the first concurrent requests. File-backed WAL with bounded busy timeout supports this single-process laboratory deployment. Foreign schemas, in-memory databases, symlink database paths and legacy-store paths are refused. No application update/delete API exists; an administrator can still modify the SQLite file. This is neither immutable audit nor a production SIEM.

Audit is mandatory. If initialization or append fails, return generic 503 and disclose no context, even when token and policy were valid. No fallback to anonymous access or legacy credentials, no recursive fabricated audit success. The only permitted persistent effect for denied requests is the audit attempt. Records describe an authentication/access decision, never workflow/business success. Separate files have no distributed transaction or automatic retention/revocation.

The original token expiry is checked again after append. If it expires during persistence, the projection is suppressed and 401 returned. The already committed allowed row still records the decision before expiry, not successful delivery; no second fabricated event or deletion is performed.
